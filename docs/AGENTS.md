# AGENTS.md - documentation site

Standalone Astro + Starlight site (own `package.json`) rendering the documentation for `@three.ez/instanced-mesh`; the library is consumed from `../src`. Run commands from `docs/`:

```bash
npm run dev      # local dev server with hot reload
npm run build    # tsc (examples) + astro check + astro build  ->  docs/dist
npm run preview  # preview the production build
```

## Layout

- `src/content/docs/**` — MDX pages, organized with Diataxis: `getting-started/` (tutorials), `basics/` (how-to), `advanced/`, `more/` (faq, tips). `api/` is GENERATED by starlight-typedoc from `../src/index.ts`.
- `src/examples/<kebab-name>/index.ts` — runnable examples embedded in pages (optional `app.ts` + local files).
- `src/pages/examples/[...slug].astro` — importmap for example dependencies.

## Conventions

- Pages need frontmatter `title` (and `description`); ordering comes from numeric filename prefixes, sidebar groups are autogenerated in `astro.config.mjs`.
- Embed an example with `<Example path="<kebab-name>" />` — auto-imported, no import statement. New example dependencies must be added to the importmap, `docs/package.json`, and the StackBlitz package.
- Load the `add-docs-page` (and `add-example`) skills from the root `.opencode/skills/` for the full procedure.

## Boundaries

- Never edit generated output: `dist/`, `.astro/`, `src/content/docs/api/`, `public/examples/`.
- Never change the library source from here: make library changes in `../src` and add a rule to the root `AGENTS.md`.
